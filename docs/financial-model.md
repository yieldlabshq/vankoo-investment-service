# Vankoo Investment financial model

This service prices invoice participations at a fixed rate determined by the auction risk grade. Investors choose how much to fund; they do not submit or override the return rate.

## Quote calculation

Let:

- `N` be the confirmed outstanding invoice balance;
- `d` be the calendar days from the quote date to the invoice due date;
- `TEA` be the investor annual effective rate for risk grade A, B or C.

The service uses a 360-day financial basis:

```text
periodRate         = (1 + TEA)^(d / 360) - 1
fundingTarget      = N / (1 + periodRate)
investorGrossGain  = N - fundingTarget

platformFeeBase    = N * monthlyPlatformFeeRate * (d / 30)
platformFeeTax     = platformFeeBase * 18%
platformFeeTotal   = platformFeeBase + platformFeeTax

mypeAdvance        = fundingTarget - platformFeeTotal
mypeTotalCost      = N - mypeAdvance
mypeTcea           = (N / mypeAdvance)^(360 / d) - 1
```

Money is rounded to two decimal places with `HALF_UP`. Rates are calculated with decimal precision and stored with twelve decimals. The last partition receives any cent-level allocation residual so all investor maturity amounts sum exactly to `N`.

The API exposes rates in percentage points with a `Pct` suffix. For example, a stored decimal rate of `0.15` is returned as `investorTeaPct: 15.000000`.

## Default pricing profile

The `demo-2026-09` defaults are:

| Risk | Investor TEA |
|---|---:|
| A | 12% |
| B | 15% |
| C | 18% |

Vankoo charges the MYPE a separate 0.30% monthly platform fee plus 18% IGV on that fee. The IGV is not platform revenue. All rates, durations and minimum tickets are configurable through the `INVESTMENT_*` environment variables declared in `application.yaml`.

These values are a launch configuration, not a guaranteed return or a substitute for commercial, accounting or legal validation.

## Lifecycle and pilot boundary

1. Invoicing creates an auction candidate through Kafka.
2. The private evaluation endpoint assigns A/B/C and confirms that the full invoice total remains outstanding.
3. The MYPE requests a quote. A newer quote supersedes an older unaccepted quote.
4. The MYPE has 24 hours to accept the exact quote; acceptance publishes the auction.
5. Funding remains open for at most seven days and always ends one day before invoice maturity.
6. Funding is all-or-nothing. Expired or administratively cancelled auctions cancel every active partition.
7. The investment request supplies amount and transaction identity only. The accepted quote determines participation and return.

For the pilot, `TotalAmount` is accepted as `N` only when evaluation confirms there are no detractions, retentions, credit notes, advances or partial payments. The long-term Invoicing contract must publish a separately calculated `NetOutstandingAmount`.

Actual wallet reservation, MYPE disbursement, collection, investor tax withholding and settlement remain Finance Service responsibilities.

## Main endpoints

- `PUT /api/v1/internal/auctions/{id}/evaluation`
- `POST /api/v1/auctions/{id}/quotes`
- `POST /api/v1/auctions/{id}/quotes/{quoteId}/accept`
- `POST /api/v1/auctions/{id}/investments`
- `GET /api/v1/auctions/{id}`
- `GET /api/v1/auctions/marketplace`
- `POST /api/v1/auctions/{id}/cancel`
- `POST /api/v1/internal/auctions/{id}/cancel`
- `POST /api/v1/internal/auctions/{id}/close`

Internal endpoints rely on private-network isolation and must not be routed through the public API Gateway.

## Database setup

Flyway owns the schema and Hibernate validates it at startup. Development databases previously generated by `ddl-auto=update` must use a fresh, empty schema before applying `V1__create_investment_schema.sql`; this project has no production data migration path in this version.
